# Project Ragnarok — Official Release Notes Template

Use this format for EVERY published game build so the website Dev Log automatically displays organized bullet lists.

Release title: `Project Ragnarok vX.YY — [Build Name]`
Tag: `vX.YY-playtest` for alpha playtests, or `vX.YY` for stable releases.

## Added
- [New feature actually present in the published ZIP]
- [New gameplay or content]

## Changed
- [Existing behaviour, controls, UI, art, or balance that changed]

## Fixed
- [Confirmed fixed bug, ideally with test performed]

## Known Issues
- [Outstanding limitation or incomplete system, if any]

Rules:
- Use one bullet per meaningful change; omit empty categories.
- Be accurate: separate implemented, verified changes from planned work.
- Mention gameplay-affecting changes and relevant compatibility notes.
- Publish notes in the GitHub Release description, not only in a commit, draft, or Codex report.
- The public website reads the release description automatically; no manual website update is needed.
- Do not mark an experimental test build as a completed milestone.
