# Project Ragnarok v0.15 — Authorized development handoff

Status: **User approved implementation** on 2026-11-22. This document is an implementation contract for the local Godot/Codex development workspace; it is **not** evidence that game code has been changed, built, or tested.

## Source of truth and safety
- Actual Godot working copy lives on the user's Windows PC (previously identified as `G:\Project Ragnarok`), **not in this website-only GitHub repository**. Locate the real project before coding; verify the version and current source. Do not invent paths, overwrite user saves, or assume web files are game scripts.
- Preserve v0.14 as a rollback baseline. Before each risky change: take source and persistent-save backups, commit incremental changes to a local feature branch, and test migration/load compatibility.
- Do not publish a v0.15 release, replace v0.14, or update the website download link until export and real two-PC tests pass.
- Diagnose before editing. Implement in small connected slices, run Godot parser/headless tests when available, and record PASS / FAIL / NOT TESTED honestly.
- Base art on the **approved** 8 model reference sheets from the conversation. They are concept images, not production-ready 3D assets; actual models/rigs must be built or sourced appropriately.
- Preserve all existing gameplay systems and use performant, authority-safe networking. No motion blur.

## P0: Multiplayer parity and death/rejoin
The user verified that host and guest could join one another's v0.14 session, but a guest could only move; guest movement animations did not play, and gameplay interactions were unavailable.
1. Trace player authority, input path, RPC validation, animation-state sync and ownership. Ensure host and client display each other walking/running and action animations.
2. Use server/host authoritative actions for guest combat, gathering, harvesting, looting, inventory transfers, workstations, crafting, building, equipment, survival state, NPC interactions and settlement actions, subject to permissions. Prevent item duplication and unauthorized mutations.
3. Persist individual guest inventories, equipment, positions, attributes, and legitimate shared world changes. Verify disconnect, reconnect, and multiple concurrent actions.
4. Both host and guest dying must leave the world/session active for survivors. On death, show `Press ENTER to create a new survivor and continue your journey through [World Name]`; ENTER is only bound to that action in death state, never while alive. Create a successor in the same persistent world; personal skills and abilities do not transfer except via established world-specific Transference Points (TP) system. No respawning the dead survivor.
5. Maintain host/world authority despite host survivor death. Explicitly verify on *two separate PCs*, both hosting directions; loopback-only tests are insufficient.
6. Menu key toggles the same menu open/closed. ESC closes the topmost open menu and must not immediately open pause; only opens pause during unobstructed gameplay. Nested views close one layer at a time.

## P1: Art, characters and performance benchmark
- Four approved body archetypes: Balanced, Lean/Wiry, Athletic/Strong, Heavy/Powerful; male and female variants (8 concept base designs). Slightly wider hips/fuller bust for female base as approved; natural and restrained anatomy.
- Character art direction: stylized 3D inspired primarily by Realm Royale characters and readable Dysmantle/Torchlight environments; strong silhouettes, expressive faces, readable gear, warm/cold light contrast. Preserve approved class-to-body **suggestions**, not restrictive morphology. All occupations available to both genders *for now*. Cosmetic appearance has **zero** inherent combat buffs.
- Shared animation-compatible skeletons where possible; tested controlled morphs; modular hair, beard, face preset, skin/eyes, scars, tattoos, equipment/clothes. Tattoos can later be added via an appropriate NPC. Diet/activity-driven shape change and NPC specializations deferred.
- Benchmark modular base pieces and NPCs, controlled emissive lighting, few shadow-casters, simplified distant meshes/materials/animations, reasonable texture memory, scalable shadows. No motion blur at any graphics setting.
- Reference minimum-class GPUs GTX 1060 / RX 580; 1080p/60 FPS Medium as **aspirational target**, not proven promise. Measure frame times, worst-case settlements, NPCs, enemies, 4-player networking and screenshot stress. Report test hardware and results; don't claim target met until verified.
- Create a first small representative scene and verify it runs before replacing all visuals.

## P1: Occupations and successor unlocks
- A recruitable occupation can also become a playable class. Recruit specialist + establish occupational infrastructure to unlock it for successor survivors **in that world**.
- NPCs earn occupation-specific XP from meaningful relevant tasks, gaining levels. When **one** NPC of a class reaches its eventual (not yet defined) threshold, unlock the occupation permanently for all future worlds. Permanent unlock persists even if NPC dies. No repeatable TP reward for additional NPCs reaching threshold.
- TP = **Transference Points**; world-specific, earned from world development/discovery, spendable by successor survivors. Never spent on permanent class unlocks; no cross-world TP carryover. Starter class passives do not bypass advanced progression/workstation requirements.
- Exact NPC leveling/thresholds and specializations deliberately deferred: build extension points, do not hardcode an invented 75% rule.

## P1: Memories of Project Ragnarok
- F12 rebindable screenshot; **1 second real-time cooldown**. Gameplay HUD excluded from captured frame without flash/flicker; menus remain visible if a menu is open. Brief subtle capture sound; failure warning.
- Filename format: `[World Name] - Day [N] - [Dawn|Morning|Midday|Afternoon|Dusk|Evening|Night|Midnight] - [HH]h[MM] - [Photographer Survivor] [and visible survivors].png`. Photographer first, use actual survivor names. Detect other on-camera character visibility with simple viewport bounds + line-of-sight as feasible; no image recognition. Sanitize invalid Windows filename chars and use capture seconds or a collision-proof ID if filename already exists; never overwrite.
- At first launch, before entering gameplay, prepare `[volume containing game executable]:\Memories of Project Ragnarok`, **at volume root**, independent of how deeply launcher/Steam installs game. If unwritable use user-writable folder, notify user. Configurable location in Settings; Desktop shortcut maintained. Do not do folder or shortcut setup upon pressing F12.
- Frame capture/encode/write should be scheduled to minimize frame stalls; bounded queue, robust error handling and no repeated directory scans per frame.
- Inventory album icon + configurable album key. Lightweight bark/thin wood photo album with newest-first, world filter, lazy thumbnails/full-size on demand. Sync when refreshed with filesystem changes. A local photo deletion requires explicit confirmation: `Are you sure you want to delete this memory?`; deletes corresponding local file only.
- Co-op: photographed survivors receive the *shared memory* via limited/rate-limited transfer to a bounded **temporary cache**, not their permanent memories folder. A recipient may save a permanent copy or dismiss. Cache expiry/size rules can be tuned; disconnected players need not receive cloud copies. Notification: `[Survivor Name] wants to share a memory with you. Press [Album key] to see your photo album.` Show unobtrusively ~20 seconds; persistent unread count on inventory album icon until reviewed. No duplicate saved file unless the recipient explicitly saves. One player deleting own memory never deletes another player's copy. Process share only when eligible named survivors are present, and avoid exposing arbitrary filesystem paths over network.

## P1: Death, graves, mourning and The Procession of the Fallen
**The supernatural ceremony is a player discovery: no spoilers in tutorial, loading screens, labels or pre-discovery hints.**
- At death, atomically record deceased survivor identity, world, place, body and **physical** inventory/tools/weapons/armour/resources; personal achievements, Trophies of Valour and TP are NOT loot in the recovery chest. Prevent duplication or loss across reconnect.
- No qualifying settlement: permanent unnamed grave at site, lootable using F; grave marker persists even after emptied. The successor gets no magically revealed death location.
- Settlement: player places Memorial Ground marker/zone as a non-spoiler tutorial step; 4 villagers construct a memorial from available village resources, with fallback when too few builders/resources or no designated space. Player can later choose memorial grounds or hall. Persistent record and marker.
- A normal raven flies from deceased body to village and announces the death; horn sounds. Ordinary villagers pause for **10 real-world seconds** mourning and then resume. If under attack or in survival-critical work, they do not stop; a senior NPC may call `[Survivor] has fallen, but now is not the time for mourning.` Defenders keep fighting.
- Meanwhile four hooded spectral pallbearers emerge and take the body for a **short** distance; **long-distance** deaths use an enormous spectral raven carrying the body. Calculate option using estimated navigable walk path/time or flight route plus ceremony overhead so arrival/laying to rest is within approximately **60 real-world seconds**. No visible teleport when observed; for extreme distances cinematic acceleration can cap duration. Spectral carriers ignored by enemies/animals/NPCs, cannot be attacked or interacted with, use lightweight visual state and host-authoritative progression. Reveal only at death.
- The dead player may follow their body on a spectator camera for the entire procession until pressing ENTER to create the next survivor, and can open character creation immediately if desired. In co-op, ceremony continues for all other players even when deceased player starts creation/disconnects; no shared clock skip. In single-player, use a controlled advance/time skip for successor arrival, without runaway hunger, crops, raids or NPC simulation.
- On arrival, the carrier lays the body at prepared memorial and a spectral loot chest appears with only physical possessions. Successor may loot via F; empty chest may despawn but memorial remains. If memorial construction lags, a provisional marker is sufficient.
- Avoid spoiler strings in visible UI: `Procession of the Fallen` is an internal development name until discovered. Make funeral ceremony graceful if world is unloaded, NPCs unavailable, concurrent deaths occur, or player disconnects.
